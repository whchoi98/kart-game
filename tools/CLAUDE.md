# Tools Module

## Role
Build, local development, QA, performance, simulation and live-verification scripts. TypeScript tools run with `npx tsx` (the root `tsconfig.json` type-checks them in `npm run typecheck`); `.mjs` tools run with `node`. None of them ships with the game. `tools/build.mjs` is the only tools file in the Docker build context (`.dockerignore` and `IMAGE_CONTEXT_EXCLUDE` list `tools/*` and `!tools/build.mjs`), because the image build runs `npm run build`.

## Key Files
- `build.mjs` - `npm run build`. Vite builds `dist/client`; esbuild bundles `dist/server/index.js` and `dist/server/verify-worker.js` (node22 ESM, every dependency inlined); stamps `<meta name="turbo-pals-build">` into index.html, writes `dist/client/build.json`, bundles `dist/client/sw.js` with the precache list, then writes `dist/build.json` (`version`, `id`, `builtAt`). QA build with the `?debug` hook: `TURBO_DEBUG_HOOK=1 node tools/build.mjs` (never deploy it).
- `dev.mjs` - `npm run dev`. Vite on http://localhost:8200 (proxies `/api` and `/healthz` to 8201) plus `tsx watch src/server/index.ts` on 127.0.0.1:8201 with in-memory rankings; allows `http://localhost:8200`, `http://127.0.0.1:8200` and up to 14 LAN IPv4 origins (the server accepts 16).
- `vite-qa.config.mjs` - `npx vite --config tools/vite-qa.config.mjs --port <PORT> --strictPort`. Dev server without HMR or file watching (restart it to see edits), `__DEBUG_HOOK__` always on, `/api` and `/healthz` proxied to 127.0.0.1:8201 with `changeOrigin: false`.
- `qa-screens.ts` - `npm run qa:screens` or `npx tsx tools/qa-screens.ts [--url http://127.0.0.1:8200] [--tracks id,id] [--out test-results/qa] [--quality high] [--width 1280] [--height 720]`. Uses `window.__turbo`; writes intro, countdown, race-early and race-mid screenshots per track and `report.json`.
- `sim-report.ts` - `npx tsx tools/sim-report.ts [trackId ...] [--cc 150] [--level hard]`. Headless CPU races and a bot time trial per track. Exports `runCpuRace` and `runBotTimeTrial`.
- `track-report.ts` - `npx tsx tools/track-report.ts [trackId ...] [--png] [--out dir]` (default `test-results/tracks`). Validates every track (normal and mirror), writes SVG plans (PNG with `--png`), exits 1 on a validation problem. Exports `analyzeTrack`, `trackSvg`, `TrackReport`.
- `gen-icons.ts` - `npx tsx tools/gen-icons.ts`. Rasterises `public/favicon.svg` into `public/icons/` (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `icon-maskable-192.png`, `apple-touch-icon.png`) with Playwright Chromium.
- `perf-race.ts` - `npx tsx tools/perf-race.ts [--url http://127.0.0.1:8244] [--tracks a,b] [--qualities low,medium,high] [--seconds 6] [--heap 0] [--cycles 0] [--alloc 0] [--governor 0] [--shadow 0] [--build 0] [--tag run] [--out test-results/perf]` -> `perf-<tag>.json`. Frame cost, draw calls, heap and optional leak, governor, shadow and scene-build probes.
- `perf-views.ts` - `npx tsx tools/perf-views.ts [--url http://127.0.0.1:8244] [--tracks a,b] [--qualities low,medium,high] [--views 12] [--width 640 --height 360] [--shots 0] [--tag views] [--out test-results/perf]` -> `views-<tag>.json`. Draw calls and triangles at fixed viewpoints.
- `perf-build.ts` - `npx tsx tools/perf-build.ts [--url http://127.0.0.1:8244] [--tracks neon-city] [--quality high]`. CPU profile of the race-scene build.
- `perf-leaks.ts` - `npx tsx tools/perf-leaks.ts [--url http://127.0.0.1:8244] [--quality medium] [--tracks sunny-meadow,neon-city,sunny-meadow]`. GPU geometry and texture leaks across race cycles.
- `perf-shadow.ts` - `npx tsx tools/perf-shadow.ts [--url http://127.0.0.1:8244] [--quality high]`. Shadow-camera texel snapping.
- `perf-probe.ts` - not a CLI: the `PROBE` string that installs `window.__perf`, imported by `perf-race.ts` and `perf-views.ts`.
- `verify-live.ts` - `npm run verify:live` or `npx tsx tools/verify-live.ts [--no-e2e] [--custom] [--out docs/quality/live-verify.json]`. Live acceptance checks of `TurboPalsStack` (topology through read-only `aws` calls, edge headers and caching, API, custom domain through `curl --resolve`, and an end-to-end verified bot submission); `--custom` runs the HTTP and E2E checks through the custom domain instead of the native CloudFront hostname. Writes the JSON report and exits 1 on any failed check. Without `--out`, `--custom` overwrites `docs/quality/live-verify.json`; the custom-domain report is kept as `--out docs/quality/live-verify-custom.json`.
- `verify-live-pwa.mjs` - `node tools/verify-live-pwa.mjs [https://my-kart.whchoi.net]`. 8 headless-Chromium checks of the deployed PWA (HTTPS, no debug hook, precache, service-worker control, offline-readiness chip, offline cold start and menu, console errors); screenshots in `test-results/live-pwa/`; exits 1 on failure.
- `prompts/` - reserved for LLM prompt files. There are none yet; keep `prompts/.gitkeep`.

## Rules
- Changing `build.mjs` changes the image asset hash and therefore triggers an image rebuild on the next deploy; other tools never do. A new script needed inside the image build gets a `!tools/<file>` exception in both `.dockerignore` and `IMAGE_CONTEXT_EXCLUDE` (same position).
- Keep `build.mjs` outputs in step with their consumers: `src/server/verifier.ts` (`defaultWorkerUrl()` expects `verify-worker.js` next to the server bundle), `src/server/config.ts` (`builtVersion()` reads `dist/build.json`), the `test -f` list in `Dockerfile`, and the service-worker build id that `tools/verify-live.ts` compares with `build.json`.
- `sim-report.ts` and `track-report.ts` are imported by `test/sim/sim.test.ts` (and `runBotTimeTrial` by `verify-live.ts`): keep their exports stable and their CLI code behind the existing main guards so importing them has no side effects.
- `verify-live.ts` needs the `aws` CLI with credentials for account `061525506239`, plus `dig`, `curl` and `bash`. Its E2E step submits a real run to the production API and then deletes the four rows it created (`DeleteItem` with the key builders from `src/server/repository.ts`); it also imports constants from `infra/lib/settings.ts`. Run it only against the build you just deployed, otherwise the honest run fails on simulation version skew (it submits the server's own `/healthz` version, so skew shows as `REPLAY_INVALID`, `TIME_MISMATCH` or `LAP_MISMATCH`, never `VERSION_MISMATCH`). The report's `build` field is the local `dist/build.json`, not the deployed build.
- The `?debug` hook (`window.__turbo`) exists only on the Vite dev servers and in `TURBO_DEBUG_HOOK=1` builds. `qa-screens.ts` defaults to `npm run dev` on 8200; the perf tools default to 8244, so start `npx vite --config tools/vite-qa.config.mjs --port 8244 --strictPort` first or pass `--url`.
- Browser tools (`qa-screens`, `perf-*`, `gen-icons`, `track-report --png`, `verify-live-pwa`) need Playwright Chromium: `npx playwright install chromium` (or `bash scripts/setup.sh --with-browsers`).
- QA, perf and track outputs go to `test-results/` (git-ignored). Two tools write committed files: `verify-live.ts` (`docs/quality/*.json`) and `gen-icons.ts` (`public/icons/*.png`, regenerate after changing `public/favicon.svg`).

## Testing
- `npm run typecheck` covers `tools/*.ts`; `npx vitest run test/sim` exercises `sim-report.ts` and `track-report.ts`.
- `build.mjs` is checked by `npm run build` itself, the Dockerfile `test -f` assertions and the `verify-live.ts` checks "Service worker served fresh", "Manifest installable" and "Shell build id matches build.json and the service worker".
