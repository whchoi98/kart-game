# Test Module

## Role
All automated tests. Vitest suites (`*.test.ts`) cover the simulation, the browser client, the server and the CDK stack; the shell harness under `test/harness/` covers the Claude Code hooks, the secret-scan patterns and the documentation and project structure. Nothing under `test/` enters the Docker build context.

## Key Files
- `sim/sim.test.ts` - deterministic math, input-log codec, track geometry (normal and mirror, via `analyzeTrack` from `tools/track-report.ts`), CPU races and the bot time trial (`runCpuRace`, `runBotTimeTrial` from `tools/sim-report.ts`), replay verification.
- `client/*.test.ts` - client tests grouped by prefix: `audio-*`, `game-*` (integration with the real `RaceWorld`), `render-*`, `ui-*`, `storage*`, `sw-policy`, `pwa-ui`, `hud-model`, `input-steering`, `kart-visual-stability`, `particles-moving-emitter`. `client/game-harness.ts` holds the shared fakes (render, audio, input, pipeline).
- `server/*.test.ts` - Fastify through `app.inject`: `http`, `rate-limit`, `runs`, `validation`, `verifier`, `repository`, `replay.integration`. `server/helpers.ts` (`testApp`, `submit`, `runBody`, `stubVerifier`, `clientFixture`) and `server/fixtures/` (`scripted-worker.mjs`, `broken-worker.mjs`). Details in `src/server/CLAUDE.md`.
- `infra/stack.test.ts`, `infra/nag.test.ts` - CDK template and cdk-nag assertions; `infra/fixtures/Dockerfile` is the stand-in image build context. Details in `infra/CLAUDE.md`.
- `harness/run-all.sh` - shell runner and assertion helpers; `harness/hooks/`, `harness/structure/`, `harness/fixtures/` hold the suites and samples.
- Project root `vitest.config.ts` - `include: ['test/**/*.test.ts']`, `testTimeout` 30 s, `hookTimeout` 120 s (CDK synth in `beforeAll`), `maxWorkers` 4.

## Rules
- Only files ending in `.test.ts` under `test/` are collected; helpers such as `game-harness.ts` and `helpers.ts` must not use that suffix. The shell harness never runs under vitest.
- Vitest uses its default Node environment and no DOM library is installed: stub browser globals explicitly in the test, and replace modules that need WebGL or canvas with `vi.mock` factories in each test file (they are hoisted, so they cannot live in the shared harness module).
- Type-checking: the root `tsconfig.json` includes `test/` but excludes `test/infra`, which `infra/tsconfig.json` (NodeNext) compiles through `../test/infra/**/*.ts`. `npm run typecheck` runs both, so keep `.js` import specifiers in `test/infra`.
- `test/sim/sim.test.ts` imports `tools/sim-report.ts` and `tools/track-report.ts`: renaming their exports or moving CLI code out of their main guards breaks the sim suite.
- Infra tests synthesize into temporary directories from props plus the `cdk.json` context and `cdk.context.json` lookups; they need no AWS credentials and no Docker. Never point `imageDirectory` at the project root in a test.
- DynamoDB Local tests are skipped unless `DYNAMODB_TEST_ENDPOINT` is set, and `repository.test.ts` throws for any non-loopback endpoint. Start it with `docker run -p 18765:8000 amazon/dynamodb-local`, then run `DYNAMODB_TEST_ENDPOINT=http://127.0.0.1:18765 npx vitest run test/server/repository.test.ts`. The tests create and delete a temporary `turbo-pals-test-<uuid>` table.
- `replay.integration.test.ts` records a fresh AI time trial with the real sim and re-simulates it in the real worker pool (`.ts` worker through tsx). It catches worker-loading breakage and nondeterminism, not trajectory changes (recording and verification run the same code), so a green run never replaces the `package.json` version bump that root `CLAUDE.md` Project Rule 2 requires.
- Some suites hard-code facts that extension steps must update: the track count (8) and `SPEC` in `client/audio-songs.test.ts`, the cue list in `client/audio-system.test.ts`, and the header literals (`DENY`, `no-referrer`, HSTS max age, `x-turbo-client-ip`) in `infra/stack.test.ts`.
- Never commit a complete credential-shaped token to fixtures, tests or docs: the harness scans the whole project with `.claude/hooks/secret-scan.sh --all`, and a quoted 8+ character value after `secret`, `password` or `api_key` with `=` or `:` counts.

## Testing
- `npm test` - every vitest suite. Subsets: `npx vitest run test/sim`, `npx vitest run test/client`, `npx vitest run test/server`, `npx vitest run test/infra`, one file (`npx vitest run test/server/runs.test.ts`) or by name (`npx vitest run -t "<pattern>"`).
- `npm run test:harness` or `bash test/harness/run-all.sh [filter]` - the filter is a substring of the test file name (`hooks`, `secret`, `structure`). Needs bash, git and node; exits 1 on any failure or when no test ran.
- `harness/hooks/test-hooks.sh` - the four hook scripts exist, are executable and parse; `.claude/settings.json` registration (matchers, the `Bash(git commit *)` `if` filter, `$CLAUDE_PROJECT_DIR` anchoring) and key deny rules; `check-doc-sync.sh` output for sample paths; `secret-scan.sh` in a throwaway git repo (exit 2 on a staged AWS key built at runtime, silent for non-commit commands and unstaged files) plus an `--all` scan of this project; `session-context.sh` output; `notify.sh` dry-run JSON.
- `harness/hooks/test-secret-patterns.sh` - every pattern label in `secret-scan.sh` has a true-positive sample in `harness/fixtures/secret-samples.txt` and is flagged with that label; every line of `harness/fixtures/false-positives.txt` stays clean; patterns use POSIX ERE only.
- `harness/structure/test-project-structure.sh` - root files, `.env.example` variables, root `CLAUDE.md` sections and npm scripts, a `CLAUDE.md` with `## Role`, `## Key Files` and `## Rules` for every `src/` directory plus `infra/`, `test/` and `tools/`, `.claude/` skills, commands and agents frontmatter, executable scripts, docs layout and ADR numbering. It then runs `harness/structure/check-docs.mjs` (bilingual parity, fenced code languages, no emoji or box drawing, relative links, reference-doc code pointers, README and CHANGELOG contracts, `.dockerignore` equal to `IMAGE_CONTEXT_EXCLUDE`). Run it alone with `node test/harness/structure/check-docs.mjs | grep FAIL`.

## How to extend
- New vitest suite: add `test/<area>/<name>.test.ts`; import sources with `.js` specifiers (`../../src/sim/race.js`), like the existing suites.
- New harness check: add `test/harness/<group>/test-<name>.sh`. `run-all.sh` sources it (it is not executed) from the project root with `pass`, `fail`, `skip`, `assert_eq`, `assert_contains`, `assert_not_contains`, `assert_file_exists`, `assert_file_executable`, `assert_json_valid`, `assert_bash_syntax`, `assert_grep_match`, `assert_grep_no_match`, `HARNESS_DIR` and `PROJECT_ROOT` in scope. There is no `set -e`; report failures through assertions, never call `exit`, and use distinct variable names because every file shares one shell.
- New check-docs rule: add a `check(desc, ok, detail)` call in `check-docs.mjs`; each prints `PASS<TAB>desc` or `FAIL<TAB>desc<TAB>detail`, which `test-project-structure.sh` turns into results.
- New secret pattern in `.claude/hooks/secret-scan.sh`: add a `<label><TAB><sample>` line to `secret-samples.txt` with the exact label. Write token prefixes as `{{MARKERS}}` (for example `{{AKIA}}`) and add the expansion to `expand_markers` in `test-secret-patterns.sh`; the check "fixtures hold no complete provider token" fails otherwise. When a pattern is relaxed or tightened, add a line to `false-positives.txt`.
