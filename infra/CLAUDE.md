# Infrastructure Module

## Role
AWS CDK v2 (TypeScript) app for the single stack `TurboPalsStack` in account `061525506239`, region `ap-northeast-2`. `cdk.json` runs it as `node --import tsx infra/bin/app.ts`; `infra/tsconfig.json` (NodeNext, strict, no emit) type-checks `bin/`, `lib/` and `test/infra/`. Request path:
- Viewer -> CloudFront over HTTPS (HTTP redirects to HTTPS); the viewer-request function stamps `x-turbo-client-ip`.
- CloudFront -> ALB over HTTP :80 with the `X-Origin-Verify` origin header. The ALB security group admits only the CloudFront origin-facing prefix list `pl-22a6434b` on TCP 80; the listener default action is a fixed 403 and one rule (priority 10) forwards only when `X-Origin-Verify` matches the Secrets Manager value.
- ALB -> Fargate ARM64 tasks on :8080 in the private subnets of the existing VPC; task egress is TCP 443 only, to ECR, CloudWatch Logs and DynamoDB. The private subnets default-route through the VPC's existing NAT gateways, but VPC endpoints owned by other stacks carry that traffic where they exist (see Gotchas).

## Key Files
- `bin/app.ts` - reads context (`account`, `region`, `vpcId`, `cloudfrontPrefixListId` fall back to `settings.ts` when missing or blank; a blank `domainName`/`certificateArn` means no custom domain; `originSecretGeneration` goes through `Number()` and defaults to 1), creates the stack and registers cdk-nag `AwsSolutionsChecks` through `cdk.Validations` (a violation fails the synth).
- `lib/settings.ts` - the only authorised target (account, region, VPC `vpc-0dfa5610180dfa628`, prefix list, AZs, public and private subnet ids), `STACK_NAME`, `PROJECT_TAG`, `APP_PORT` 8080, `ORIGIN_VERIFY_HEADER`, task size 1024 CPU / 2048 MiB, 2..6 tasks, scaling targets (CPU 60 %, 600 requests per target), `CUSTOM_DOMAIN`.
- `lib/stack.ts` - `TurboPalsStack`: safety guards, `Project=turbo-pals` tag, construct assembly, `PUBLIC_ORIGIN`/`ALLOWED_ORIGINS` container env, 7 outputs (`SiteUrl`, `NativeSiteUrl`, `DistributionId`, `AlbDnsName`, `ClusterName`, `ServiceName`, `TableName`).
- `lib/network.ts` - `Network`: `Vpc.fromLookup` of the existing VPC (cached in `cdk.context.json`) and the subnet selections; checks the resolved subnet ids against `settings.ts`. Creates nothing.
- `lib/data.ts` - `Data`: DynamoDB `Rankings` table (`pk`/`sk` strings, on-demand, PITR, deletion protection, RETAIN, no GSI or TTL) and the origin-verify secret (generation N, plus N-1 while rotating).
- `lib/logs.ts` - `AccessLogs`: S3 bucket for CloudFront (`cloudfront/`) and ALB (`alb/`) access logs, 30-day expiry, RETAIN.
- `lib/service.ts` - `Service`: 2 security groups, ALB, listener, origin rule, target group (`/healthz`), `DockerImageAsset` (linux/arm64), ECS cluster (Container Insights), log group, Fargate task definition and service, autoscaling, task-role policy. Exports `IMAGE_CONTEXT_EXCLUDE`.
- `lib/edge.ts` - `Edge`: CloudFront distribution (default, `/assets/*`, `/api/*` behaviors), viewer-request function (`VIEWER_IP_FUNCTION_CODE`), response headers policy built from `src/shared/csp.ts`, asset cache policy, asset origin request policy, optional custom domain with TLSv1.2_2021 and SNI.
- Related root files: `cdk.json` (app, feature flags, context incl. `domainName` and `certificateArn`), `cdk.context.json` (checked-in VPC lookup cache), `Dockerfile`, `.dockerignore`.

## Rules
- The stack owns no VPC, subnet, route table, route, NAT gateway, internet gateway, EIP, VPC endpoint, transit gateway attachment or flow log, and exactly two security groups. `test/infra/stack.test.ts` and the `tools/verify-live.ts` check "Stack owns no VPC / subnet / NAT / route / IGW / endpoint" assert this; adding a VPC endpoint breaks both.
- The target environment is hard-guarded in `stack.ts` (account, region, VPC, prefix list, `domainName` must equal `CUSTOM_DOMAIN`, certificate must be a us-east-1 ACM ARN in the target account, domain and certificate set together). Changing any of it means changing `settings.ts`, the `cdk.json` context and the constants in `test/infra/stack.test.ts` together.
- `network.ts` only compares subnet ids when the lookup returned the real VPC (a fresh checkout's first synth gets a dummy). Refresh `cdk.context.json` (`cdk context --clear`) only after verifying the VPC routes.
- Security group rules are fixed: ALB ingress = prefix list on 80, ALB egress = task SG on 8080, task ingress = ALB SG on 8080, task egress = 443 to `0.0.0.0/0`. A new port changes the security-group tests and the live checks "ALB SG admits only the CloudFront prefix list ..." and "Task SG admits only the ALB SG on 8080".
- The origin secret is a CloudFormation dynamic reference. Never pass it to the task environment, IAM policies or outputs (test "keeps the generated secret out of the task, IAM policies and outputs"). Rotate with `-c originSecretGeneration=<N>` and then record `"originSecretGeneration": <N>` in `cdk.json` (`docs/runbooks/rotate-origin-secret.md`). Never rename the generation-1 logical id `OriginVerify`. The distribution depends on the listener rule so the ALB accepts a new value before CloudFront sends it.
- No dependency cycles: the distribution may reference the ALB but never the task definition. Container env that needs the distribution domain is added in `stack.ts` with `container.addEnvironment`.
- `IMAGE_CONTEXT_EXCLUDE` must equal `.dockerignore` (same patterns, same order). `test/harness/structure/check-docs.mjs` checks it (`npm run test:harness`); vitest does not. The list decides the image asset hash, hence image rebuilds and `APP_VERSION` (`<package.json version>+<asset hash first 12>`).
- cdk-nag is live (`nag.test.ts` expects an extra bucket without `enforceSSL` to fail synthesis with `AwsSolutions-S10`). Justify every exception next to the resource with `cdk.Validations.of(construct).acknowledge({ id, reason })`; the current ones are CFR1, CFR2, CFR4, CFR5 (`edge.ts`), SMG4 (`data.ts`), S1 (`logs.ts`), ECS2 and IAM5 (`service.ts`).
- Security header values live only in `src/shared/csp.ts` (shared with the server). A new CloudFront behavior goes into `additionalBehaviors` spreading `...common`, so it gets the viewer IP function and the response headers policy (tests assert both on every behavior).
- New container env goes into the `environment` block in `service.ts` or `addEnvironment` in `stack.ts`, never a secret; also update `src/server/config.ts` and the test "configures the server through non-secret environment variables". A new output also updates the sorted list in the test "exports the operational outputs".
- The task role allows only `dynamodb:GetItem`, `PutItem`, `DeleteItem` and `Query` on the table ARN; widen it only together with `src/server/dynamo-repository.ts`, the test "grants the task only item/query access to its own table" and `docs/reference/data.md`.
- Custom domain: `domainName` and `certificateArn` come from `cdk.json` context and must be set or cleared together; to serve only the native hostname pass both `-c domainName=` and `-c certificateArn=`. The CNAME `my-kart.whchoi.net` -> distribution lives in a DNS zone in another AWS account (`docs/runbooks/custom-domain.md`). `VIEWER_CERTIFICATE_ARN` in `settings.ts` is exported but unused.
- Table and log bucket are RETAIN (the table also has deletion protection); only the log group is DESTROY.
- Deploy only through `docs/runbooks/deploy-production.md`: `npm run deploy` (`cdk deploy --require-approval never --outputs-file cdk-outputs.json`), then `npm run verify:live`, `npm run verify:live -- --custom --out docs/quality/live-verify-custom.json` (without `--out` it overwrites `docs/quality/live-verify.json`) and `node tools/verify-live-pwa.mjs`. It needs Docker (linux/arm64 image build) and credentials for the target account. `cdk-outputs.json` is git-ignored.
- Never destroy `TurboPalsStack`, or delete its table or secrets, unless the user explicitly asks; `.claude/settings.json` denies `npx cdk destroy*`, `cdk destroy*`, `aws cloudformation delete-stack *`, `aws dynamodb delete-table *` and `aws secretsmanager delete-secret *`. Procedure: `docs/runbooks/teardown.md`.
- After any change here, also update `docs/architecture.md` (Infrastructure), `docs/reference/iac.md` and the affected runbooks in `docs/runbooks/`.

## Testing
- `npx vitest run test/infra`: `stack.test.ts` (template assertions) and `nag.test.ts` (cdk-nag). Both synthesize into temporary directories with the `cdk.json` context and `cdk.context.json` lookups, need no AWS credentials or Docker, and pass `imageDirectory` = `test/infra/fixtures/` (a minimal `node:24-alpine` Dockerfile) instead of the project root.
- The tests build the stack from props, so the default synth has no custom domain; a dedicated test covers the custom-domain branch.
- `npm run typecheck` (includes `tsc --noEmit -p infra/tsconfig.json`) and `npm run synth` (`cdk synth --quiet`, runs cdk-nag).

## Gotchas
- Three health checks differ on purpose: ALB target group every 15 s, ECS container check every 30 s, Dockerfile `HEALTHCHECK` every 20 s (local `docker run` only; ECS ignores it).
- Keep-alive order must hold: server 65 s > ALB idle 60 s > CloudFront origin keepalive 30 s.
- The task egress path is not only the NAT gateways. A read-only check on 2026-10-18 found endpoints owned by other stacks in the VPC: S3 and DynamoDB gateway endpoints on both private route tables, and `ecr.api`, `ecr.dkr` and `logs` interface endpoints with private DNS whose security groups admit `10.100.0.0/16` on 443. Private DNS sends ECR and CloudWatch Logs calls to those endpoints, so if their security groups stop admitting the task subnets, image pulls and log writes fail while the NAT routes still look healthy. No test or live check covers these endpoints (check 13 only inspects the default routes).
- Error responses are never cached at the edge (TTL 0 for 400, 403, 404, 405, 414, 416, 500-504); no cache invalidation is needed after a deploy because index.html is not cached and `/assets/*` names are content-hashed.
